# V19 严格设计复评

日期：2026-08-14（Asia/Shanghai）

## 本轮判断

V18 已经具备稳定发布、证据降级和响应式基础，但首页右侧仍以抽象圆环解释“我们会核验”，读者需要阅读多处小字才能知道这次实际查到了什么。三个路线章节也有重复的“数据面板 + 长文 + 列表”节奏，信息正确，却没有把最重要的差异尽快交给第一次访问的人。

V19 的目标不是模仿 Apple、Stripe、Linear 或获奖网站的外观，而是迁移其中适合本站的原则：一屏一个主命题、真实证据承担视觉角色、网格层级精确、行动路径尽量少。

## 已实施

- 首屏主命题改为“先知道买的是什么，再决定要不要用”，直接对应网络服务和 AI 订阅的核心风险。
- 把抽象核验圆环替换为本轮真实结果：可打开入口、已检查客户端版本、官方文件直链与公开模型记录。
- 在首屏明确“入口可用不等于套餐价格已经确认”，避免自动检查状态被误解为商品全面核验。
- 网络服务与模型评测路线删去重复列表，把边界合并进自然段；保留 AI 路线的四个直接子入口。
- 不新增运行时动画、滚动接管、WebGL 或装饰脚本；动态数字仍来自现有同步数据。
- 生成并人工复核新版社交分享图 `public/og-live-proof-v19.jpg`：中文逐字正确、1200×630、约 89KB，缩略图层级清楚。
- 用真实设备模拟复核 390×844 与 320×780：无横向溢出，主按钮 54px、菜单按钮 44px，菜单展开后完整落在视口内。
- 修复核心样式只由首页间接加载的问题：现在由根布局统一加载，直接打开 `/ai`、`/benchmarks`、`/downloads` 等内页也有完整样式；同时合并为单一 CSS 请求，避免性能回退。

## 必须通过的门禁

- 文案、链接、动态数据、静态导出与安全门禁全部通过。
- 桌面与 390px、320px 手机宽度均不得横向溢出。
- 首屏数据不能写死；读取异常必须继续显示边界，而不是伪装为成功。
- 所有主按钮至少 44px，键盘焦点、减少动态效果和语义结构继续有效。

## 仍然不能宣称

- 本轮不能证明网站已达到或获得 Awwwards、Webby、FWA、CSSDA 等外部评审认可。
- 实验室和浏览器验收不能替代至少 28 天真实 Core Web Vitals、真实设备与真实用户任务完成数据。
- “最高质量”只能作为持续审查方向，不能用自评分或一次构建成功宣布永久完成。

## 最终验收结果

- `npm run verify:publish` 完整通过：97 个公开入口、4 个客户端项目、13 个推广/关键入口、4 个官方直链、3 个本站备用文件、4/6 项当前或七日内最近可信价格证据。
- 生产依赖安全审计 0 个已知高危漏洞；编辑门禁、ESLint、38/38 自动测试均通过。
- 32 个静态页面全部生成，GitHub Pages 5/5 发布包测试通过；首页仍只加载一份合并后的关键样式。
